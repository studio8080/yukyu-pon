# アクセス解析（GA4）の準備メモ

作成: 2026-10-07。**まだ有効にしていない。**

> **2026-10-07 運営者の決定: 当面は使わない。** 公開直後は Search Console と Bing のデータで足りる。
> 利用者が増えたら「説明ページを別サブドメインに分けて計測する」案を検討する。

## 決めたこと
- GA4 は料金・規約などの静的ページ（`public/*.html`）だけに入れる。アプリ本体（`index.html`・`src/`）には入れない。
- GA4 プロパティ「有休ポン」（studio@、アカウント「ここ企画」408610086、プロパティ 557935295）、
  ウェブストリーム「有休ポン（料金・規約ページ）」16058164045、**測定ID `G-J91XL10BCE`**（1 と 0 は数字）。
  拡張計測はオフ（ページビューのみ）。
- 計測は `public/analytics.js`（全銀ポンと同じ方式: URL のクエリ・ハッシュを除く、参照元はドメインだけ、
  Google シグナル・広告オフ、DNT/GPC を尊重、EU は同意なしでは計測しない、無効化ボタン）。本番のドメイン以外では送らない。

## 保留の理由（運営者の判断待ち）
静的ページはアプリと**同じオリジン**（https://yukyu.kokokikaku.com）なので、localStorage を共有する。
静的ページで動く gtag.js も、仕組みのうえでは従業員のデータ（`yukyu-pon:v1`）を読める。
アプリ本体に入れるより機会は減る（アプリを使っている画面では動かない）が、ゼロではない。
完全に分けるなら、説明ページを別のサブドメイン（例: `about-yukyu.kokokikaku.com` や会社サイトの下）に置き、そちらだけで計測する。

## 有効にする手順
1. `public/analytics.js` の `ENABLED` を `true`
2. `public/privacy.html` の3章を、下の公表文に差し替える（外部送信規律の公表）
3. `public/llms.txt` の「アクセス解析」の行を直す
4. push → GA4 のリアルタイムで自分の閲覧が見えるか確かめる（測定IDは1文字ずつ照合）
