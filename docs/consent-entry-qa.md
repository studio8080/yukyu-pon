# 閲覧時の必須同意を利用開始へ分ける（未公開の修正）

基準main: a9e34ac51b905fa71b7ec6ebe410c56e06c47262。もしも広告停止PR8を保持する。実装対象は入口と同意画面のみ。媒体登録の復旧・返信・再登録・広告再開、PR承認・merge・deployはこの作業で行わない。

## 動作とデータ

トップ・ルール・更新情報、静的な記事/料金/規約/プライバシーは閲覧だけで同意を要求しない。ツールの入力/編集/サンプル・取込・設定へ進む明示操作にだけ同意を求める。元の注意3点と規約チェックは保持する。

取消・閉じる・Esc・ブラウザ戻るでは保留アクションを破棄し、acceptedAtを変更しない。開き直しはチェック未選択。連続要求は最初の1操作だけ保留し、確認連打で二重登録しない。既にacceptedAtがあれば従来どおり利用できる。保存済みの一覧閲覧・管理簿/本人通知の印刷やExcel・バックアップは遮らない。データ型/保存version/計算エンジン/広告設定は変更しない。

## 自動検証

`src/lib/toolConsent.test.ts` は開始・未選択・同意・拒否/閉じる/戻る・再開始・連続操作・同意保存失敗・既存同意・保存データ/残高/年5日/管理簿の非変更を確認する。`src/consentViews.test.ts` は実際のAppのHTMLを生成し、初回説明と公開リンクの表示・同意画面の非表示、利用開始画面の規約/注意/退出導線、静的ページの独立を確認する。HTML生成・状態遷移の試験は実ブラウザQAとは区別する。

既存の月次確認・計算・Excel・保存移行・広告停止テストも全件実行する。もしも3件のenabled:false、両広告枠のA8選択、AdSlotのPro時抑止を維持する。実データは使わない。

## 実ブラウザで残すべき確認

1. 空のテスト用originで初回トップを開き、チェックなしで説明・記事・料金・規約・ルール・更新を読める。公開リンクは新しい同意を保存しない。
2. 「サンプルで試す」「1人ずつ入れる」、休んだ日/取込/設定、保存済みの人の編集、出勤率確認の入口でだけ確認画面が開く。サンプル/従業員データは未同意の間に作成されない。
3. チェックなしは開始不可。同意確定で要求した操作が1回だけ実行される。既存同意済みなら再表示しない。拒否・X・Esc・背景クリック・戻るは操作を破棄し、再訪問でチェックが未選択。規約リンクを読んだだけでは同意にしない。
4. 人工fixtureで既存データを持つ未同意状態も確認し、一覧・管理簿・印刷/Excel・バックアップを取得できる。月次確認・取得/延期/取消・再読込・バックアップ復元は同意済みで回帰確認する。
5. PCと375pxで公開情報バー・同意画面・チェック・両ボタンを確認。キーボードTab/Shift+Tab、Esc、閉じた後のフォーカス復帰、印刷で同意UIが出ないことを確認する。

ChromeのURL安全停止が出た場合はexact URL・操作・errorを記録して停止し、別URL/ブラウザ/経路で同じ停止を迂回しない。コード試験とブラウザ未実施を混同しない。
