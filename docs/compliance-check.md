# 法令まわりの確認メモ（社内用）

確認日: 2026-10-12 ／ 対象: 有休ポン（運営: ここ企画。個人事業の屋号。国内むけ。インボイス未登録）

> これは弁護士・社労士の意見ではない。条文と公的な解説を読んで整理したメモ。
> 全銀ポンの `docs/compliance-check.md` と同じ設計（規約・表示・決済）にそろえている。
> 機能を足すとき（とくに従業員のデータを外へ送る機能、解析タグ）は、ここを見直す。

## まとめ

**条件つきで進めてよい。** 従業員のデータを当社が取得しない作り（ブラウザ内だけで計算・保存）なので、
従業員の個人情報について当社は委託先にも取得者にもならない。表示まわり（特商法・個情法・外部送信）は今回そろえた。
残りは下の「やること」。

## リスク

| リスク | 重さ | 手当て |
|---|---|---|
| 計算の誤りで年5日の違反を見落とす | 高 | 条文の例をテストに書いてから engine を直す（AGENTS.md 1章3）。迷ったら労働者に不利にならない側。画面と README で扱わないことを明記 |
| 利用者が就業規則と違う設定で使う | 中 | 一斉付与・引っ越しはチェックリストで事前確認。「計算結果は就業規則・法令と照らして確認」を規約と画面に |
| ブラウザのデータが消える | 中 | 自動バックアップ・ファイル保存・復元ポイント。規約2条4項 |
| サポートで従業員の名簿を受け取ってしまう | 中 | 「名簿やバックアップを送らないで」を `tokushoho` `privacy` に明記。届いたら読まずに削除して、その旨を返信 |
| 支払いが止まった契約にキーが出続ける | 低 | Stripe 側の設定で止める（確認項目8）。加えて Functions でも再請求中（past_due）は期間の初日から30日＋3日、未払い（unpaid）は支払い済みの期間までに限る（2026-10-15。全銀ポンは Stripe 側の設定だけ） |

## やること（優先順）

1. 支払いリンクを作るとき、カスタムテキストに確認の表示を入れる（launch-checklist 3-2）
2. 共用 Stripe の再試行失敗時の動作と、支払い失敗メールの設定を確かめる（launch-checklist 3-5）
3. 販売開始前に `node tools/preflight.mjs --sale`、最初の実購入で launch-checklist 7章の項目を確かめる（テスト購入はしない。6章）
4. Stripe・Google・GitHub の二段階認証を確かめる

## 専門家に見てもらうとよい所

- 社会保険労務士法27条との関係（道具の提供にとどまるか）
