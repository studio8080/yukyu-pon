# 有休ポン（yukyu-pon）

有給休暇の付与日・付与日数・残日数・2年の時効・**年5日の取得義務**を、
**名簿（氏名・入社日・週の勤務日数）と休んだ日だけ**で自動計算するブラウザアプリ。
全銀ポンと同じ設計思想（登録不要・データはブラウザの外に出さない・単機能）。

- 公開URL: https://yukyu.kokokikaku.com/ （GitHub Pages。`main` に push すると GitHub Actions でテスト・ビルドして公開）
- リポジトリ: https://github.com/studio8080/yukyu-pon
- 運営: ここ企画（https://kokokikaku.com/）

対象: 従業員5〜30名ほどの小規模事業者・店舗・クリニック。勤怠 SaaS を入れるほどではないが、
Excel の有休管理が壊れかけている会社。

## 1. 設計の決めごと

| 決めごと | 理由 |
|---|---|
| 従業員のデータを扱うサーバー・DB・解析タグなし。保存は localStorage、控えはファイル | 氏名と休んだ日は個人情報。本番の CSP `connect-src` はキー更新先（Cloud Functions）だけ。送るのはライセンスIDだけ |
| 入力は「氏名・入社日・週の勤務日数（＋週30時間以上か）」と「休んだ日」だけ | 打刻・シフト・出勤日数は持たない。重い勤怠 SaaS にしない |
| 基本は自動、例外は人が上書き（付与日数・8割未満・会社独自の上乗せ・移行残） | 9割の人は何も触らずに正しく、残り1割は手で直せる |
| 迷ったら**労働者に不利にならない側**で判定する | 年5日は期間が重なっても按分せず、それぞれの期間で5日を見る／移行残は時効の遅い側に割り当てる |
| **社労士を挟まない前提で、判断の要る設定は利用者に事前確認させる** | 一斉付与への切り替え・Excel からの引っ越しは、チェックリストに全部チェックしないと進めない。初回は利用規約への同意 |
| **データを人質にしない** | Pro が必要になっても、閲覧・管理簿の出力・バックアップは止めない。止めるのは「無料の人数を超えて新しく追加する」ことだけ |
| PDF は jsPDF ではなく**ブラウザの印刷（A4横）** | 日本語フォントの埋め込み（数MB）が不要 |
| SheetJS は npm 版（0.18.5、既知の脆弱性あり）ではなく **公式配布（cdn.sheetjs.com）の 0.20.3 の tarball** を package.json で指定し、ビルドに同梱する | 外から来た Excel を読むため。実行時に外部の CDN からは読まず、必要になったときだけ自分のサイトのチャンクを読み込む |

### Gemini 案から変えた点（法令との照合の結果）

1. 週の日数だけでは区分を決められない → 「週30時間以上」を入力に追加。シフト制は年間の所定労働日数で判定。
2. 契約変更で週日数を上書きすると過去の付与まで変わる → 契約は履歴で持ち、付与日時点の契約で決める。
3. 繰り越しと2年の時効が無かった → 付与ごとのロットで残高を持ち、2年で消す。
4. 出勤率8割未満のフラグが1つだけ → 付与の回ごとに記録。勤続年数は進む。
5. 6か月後の数え方 → 8/31 入社は 3/1（民法143条）。
6. 一斉付与の前倒し → 前の付与から1年を超えない／前倒しの回は次の段階の日数、をテストで保証。
7. 年5日の対象は「法定の付与が10日以上の回」だけ。会社独自の上乗せでは判定しない。
8. 管理開始前に終わった期間は「未達」と言わない（記録が無いだけ）。

### 有休ポンが決めたルール（2026-10-03。利用者が事前に確認する前提）

- **一斉付与の前倒し**: 上の表のとおり。切り替えるとき、設定画面で3項目のチェック（就業規則に定めがある／前倒しの回は次の段階・1年を空けない／短縮期間は全出勤とみなす）を必須にし、確認日時を `settings.uniformConfirmedAt` に残す。
- **Excel からの引っ越し**: 「管理開始日」の残日数を出発点にする。残日数は**直近の付与から順に**割り当てる（時効の遅い側＝働く人に不利にならない）。管理開始日より前に休んだ日は残日数から引かず、年5日の集計にだけ使う。管理開始前に終わった期間は年5日を判定しない。取り込み時に3項目のチェックを必須にする。各人の「残高・移行」で直せる。
- **退職した人の年5日**（2026-10-15）: 在籍中は退職日を期限として知らせる。退職した後に5日に届かなかった期間は `retired`（「退職（5日に届かず・判定なし）」）にして未達の警告をやめる。退職を明示した行政資料は未確認で、パンフ Q13・Q14（休職・育休で履行不能な場合は違反を問わない）を参考にした有休ポンの扱い。「対象外」とは表示しない。
- **休職・育休で取らせることができなかった期間**（2026-10-15）: `GrantAdjustment.infeasible = { reason }` を「付与と5日」で記録できる。期限を過ぎて5日に届かなかった期間だけ `infeasible`（判定なし）にし、管理簿に事情を書く。期間の途中は記録があっても知らせ続ける（Q14: 途中で復帰したら5日が要る）。
- **計画的付与の確認**（2026-10-15）: 上の表の `plannedCheck`。5日を下回る人は登録の前に知らせて既定で外し（事情があればチェックで含められる）、まだ年休が無い日・退職日より後の日は年休として登録しない。

### 扱わないこと

- 10日を分けて付与する方法（労基則24条の5第4項）。小さな会社ではほぼ使われない。合計10日に達した日から年5日の期間が始まるため、上書きでまねても年5日の期限は正しく出ない（画面でも「年5日の表示を使わない」と案内）
- 年5日の期間が重なったときの按分（同第2項）。按分せず、各期間で5日を確認する（厳しい側なので、守れていれば違反にならない）
- 出勤率の自動計算（出勤日の記録を持たない設計。確認の促しと記録で代替）
- 私傷病の休職などの個別規定 → 出勤率の確認と付与日数の手動上書きで対応。試用期間は勤続に含む（入社日は試用期間の初日）。業務上の傷病・育児介護休業・産前産後休業は39条10項で出勤とみなすので、付与を減らさないよう画面で案内する
- 時季変更権（39条5項）、年休の日の賃金（39条9項）。画面では、年休の取得を理由に皆勤手当・賞与で欠勤扱いにできないこと（附則136条）、年休の買上げの予約で日数を減らせないことだけ書く。「休んだ日」に買上げ・特別休暇・欠勤を入れないよう案内する
- 在籍出向の人の年5日（出向元・出向先・本人の取り決めによる。パンフ Q8）
- 法定を超える育児休業の延長部分の出勤率の扱い（未確認）

## 3. データを守る仕組み（`src/lib/backup.ts`・`src/store.ts`）

1. **自動バックアップ**（Chrome・Edge）: 利用者が選んだ端末上のファイルへ、変更のたびに上書き保存（File System Access API）。保存先の「場所」だけを IndexedDB に覚える。ブラウザを開き直すと許可の取り直しが要るので、画面上部に「再開する」を出す。そのファイルから戻せる。
2. **ファイルに保存・戻す**（全ブラウザ）: JSON。7日以上バックアップが無く変更があれば、画面上部で催促する。
3. **復元ポイント**: 取り込み・削除・戻す・すべて消すの前と、毎日最初の変更時に自動で控え（最大12件、localStorage）。
4. `navigator.storage.persist()` を要求して、容量不足でブラウザに消されにくくする。
5. **バックアップの暗号化（任意）**: 「ファイルに保存」でパスワードを付けると、PBKDF2（SHA-256・60万回）→ AES-GCM 256bit で暗号化する（`src/lib/crypto.ts`）。
   パスワードは保存しない。忘れると誰も戻せない。自動バックアップのファイルは暗号化しない（共有・同期フォルダに置かないよう画面で案内）。

### そのほかの安全対策
- **他のサイトへの埋め込みを拒否**（`src/main.tsx`）。iframe の中では画面を出さない。GitHub Pages ではヘッダー（frame-ancestors）を付けられないための代わり。
- **広告（アフィリエイト）は無料プランの人にだけ**（`src/lib/ads.ts`・`src/components/AdSlot.tsx`、2026-10-15 運営者の決定）。ホームとルールのページの下に1枠。管理簿・お知らせ・印刷・設定には出さない。
  従業員のデータを守るため、広告のスクリプトは読み込まない。A8.net・もしもの**テキスト広告・バナー広告（a と img だけのタグ）**を `isSafeAdTag` で許し、CSP は `img-src` に両社の計測画像・バナー画像のドメインを足しただけ（`connect-src`・`script-src` は変えない）。2026-10-15 にもしもの3件（勤怠クラウド・Relix勤怠＝ホーム、Remoba労務＝ルール）と A8.net の2件（弥生給与 Next＝ホーム・ルール、マネーフォワード クラウド＝ルール）を登録。
- **従業員の顔写真（任意）**は 96px の JPEG に縮めてブラウザとバックアップにだけ入れる（`src/lib/photo.ts`）。容量を抑えるため復元ポイントには入れない。
- **アクセス解析（GA4）は料金・規約などの静的ページだけ**（`public/analytics.js`、2026-10-12 運営者の決定でオン）。アプリ本体（`index.html`・`src/`）では読み込まない。
  ページの閲覧だけを送り、URL のクエリ・ハッシュは除く。Google シグナル・広告はオフ。DNT/GPC を尊重し、privacy.html の5章で無効にできる。
  静的ページはアプリと同じオリジンで localStorage を共有する（gtag.js も仕組みのうえでは読める）点は承知のうえで有効にした（`docs/analytics-plan.md`）。

## 4. 料金と課金（2026-10-06 決定。全銀ポンと同じ構成）

| プラン | 在籍人数 | 月払い | 年払い |
|---|---|---|---|
| 無料 | 5人まで | ¥0 | — |
| Pro | 30人まで | ¥480 | ¥4,800 |
| ビジネス | 無制限 | ¥980 | ¥9,800 |

すべて税込。機能は全プラン同じで、違いは在籍人数（退職者は数えない）だけ。上限を超えても閲覧・管理簿・バックアップは止めない。

決めた理由: 有給管理は勤怠 SaaS のおまけ機能として安く（HRMOS勤怠は30人まで無料、有料は1人100〜200円・最低月2,000〜3,300円）、
単体で高くは売れない。「Excel 管理の置き換え」として最低料金より安く、即決できる値段にした。Pro は全銀ポンと同額。
30人を超える会社・社労士事務所・複数店舗はビジネスへ。

仕組み（全銀ポンの `functions/` と同じ設計。運営者の手順は `docs/launch-checklist.md`）:

- Stripe のサブスク（月・年、自動更新）→ Webhook → Cloud Functions（Firebase `misefits` に codebase `yukyupon` で相乗り、asia-northeast1）
  → 署名付きキー（YP1-、Ed25519。Pro は `n:30`、ビジネスは上限なし）を発行してメール。
- キーの寿命は最長30日。ブラウザが「期限10日前」か「前回確認から7日」でライセンスIDだけを送って取り直す。Stripe で解約を確かめたときだけ 410 → キーを外して無料に戻る。Stripe に照会できず判断できなければ 503 で、ブラウザはキーを消さない。
- 使える最終日は契約の状態で決める（`functions/billing.js` の `entitledUntilOf`）。契約中は期間の末日＋3日、日付指定の解約はその日＋3日、再請求中（past_due）は期間の初日から30日＋3日まで、未払い（unpaid）は今の期間の初日＋3日、一度も払われていない契約には出さない。
- 共用の Stripe アカウントなので、**商品ID（`functions/plans.js`）で絞る。空なら何もしない。**
- Webhook はイベントIDで二重処理を防ぎ、メールを送れなければ 500 で再送させる（共通メモ5章の4）。
- 秘密鍵: `C:\Users\chaha\.yukyu-pon\license-private.pem`（リポジトリ外。要バックアップ）。公開鍵: `src/lib/license.ts`。
- 手動発行: `node tools/issue-key.mjs --months 12 --plan pro|business [--id ライセンスID]`（台帳 `tools/issued-keys.csv` は gitignore）。
- 確かめ方: `functions/test/functions.test.js`（Webhook・キー更新の全経路。イベントは Stripe の実際の形）、`src/lib/license.test.ts`・`plan.test.ts`（サーバーのキーをブラウザが読めるか・自動更新）、`tools/preflight.mjs`（設定の照合。販売前は `--sale`）。

### 画面のデザイン（2026-10-07 作り直し。コンセプト「休暇届にハンコをポン」）

- **色**: 緑 `brand-500 #10a56e`（主役）・文字 `ink #0c3b2e`・地 `paper #f3f7f5`・線 `line #e2ebe6`。
  黄 `sun`（注意・ロゴの「ポン」の効果線）、朱 `shu`（至急・未達成）は**状態を表すときだけ**使う。飾りに使わない。
- **書体**: 見出し・数字・ロゴは丸ゴシック（`.font-display`、自前で配信する `public/fonts/yukyu-rounded-800.woff2`）。
  助詞などは `<small>` で小さくする（「有休<small>の</small>残り」）。本文は端末の標準のゴシック。
- **部品**: ボタンは丸い錠剤形（主ボタンは白丸の矢印付き）、面は角丸20〜28px、小見出しは四角マーカー（`.sq-label`）。
  年5日を達成した人には緑の丸いハンコ（`<Stamp>`）を押す。統計の数字は大きく、単位は小さく。
- **外部に出さない**: フォントも画像も同じオリジンから。Google Fonts などを読み込まない（CSP の `font-src 'self'`）。
- **文字を足したら** `python tools/subset-font.py <MPLUSRounded1c-ExtraBold.ttf>` でフォントを作り直す
  （無い字は本文の書体で出るので壊れはしないが、見た目が混ざる）。元の TTF は google/fonts の `ofl/mplusrounded1c`。
- ロゴ・アイコン・OGP 画像（`public/logo*.png`・`icon-*.png`・`favicon-*.png`・`og.png`）は同じ書体で作った画像。
